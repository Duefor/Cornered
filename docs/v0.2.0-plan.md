# v0.2.0 需求与设计

> 本文是 0.2.0 的需求基线。实施时按「实施顺序」推进，每完成一节勾掉。

## 1. 出牌表现统一

**现状**：只有单体攻击牌会进入「选择目标」状态；技能牌（自身 / 全体）点一下立刻结算，没有任何反馈动画。

**目标**：所有牌打出时都有「框选 + 小弹出」的表现。

**方案**

1. 点任意一张手牌 → 该牌从手牌扇里**抬起、放大**到屏幕中部偏下，外框高亮（框选态），手牌区其余牌变暗。
2. 此时：
   - 单体牌：点敌人确认（沿用现有目标逻辑）；
   - 自身 / 全体牌：点「确认」按钮或再点一次该牌确认。
3. 确认后播放打出动画（缩回 + 淡出），牌进入弃牌堆 / 消耗堆。

**待定**：自身 / 全体牌要不要「第二次点击确认」（统一两段式，更符合观看特效的诉求）还是「弹出后自动打出」。

## 2. 状态栏下移到屏幕下方

**现状**：玩家生命条、格挡、状态徽章在屏幕顶部；手牌和能量在底部。

**目标**：玩家状态集中到屏幕下方（参照杀戮尖塔：角色状态在左下，手牌在其上）。

**方案**：底部改为三层

```
┌─────────────────────────────┐
│                             │
│          敌人区域            │
│                             │
├─────────────────────────────┤
│   手牌（叠扇）               │
├─────────────────────────────┤
│ ❤ 68/68  ▮▮▮  🛡4  力2 易1 │  ← 生命条 + 格挡 + 状态
│ ● ● ● (能量)      [结束回合] │
└─────────────────────────────┘
```

顶部只保留：回合数、抽牌/弃牌数、退出。

## 3. 能力卡 + 卡牌数据化

### 3.1 能力卡（Power）

**现状**：`CardType.Power` 枚举已存在但没有实现，也没有任何能力牌。

**目标**：加入持续生效、打出后不进入弃牌堆的能力牌，效果参考杀戮尖塔。

**需要的机制**：一张能力牌 = 一组「触发条件 → 效果」，在战斗中常驻。初版触发器只需要覆盖：

| 触发时机 | 例子 |
| --- | --- |
| 战斗开始 | 每场战斗开始获得 5 点格挡 |
| 回合开始 | 每回合 +2 力量（恶魔形态） |
| 回合结束 | 回合结束获得 3 格挡（金属化） |
| 打出攻击牌后 | 每打出 3 张攻击牌抽 1 张 |
| 受到伤害后 | 受伤时对攻击者施加 1 层虚弱 |
| 格挡保留 | 回合开始时不再清零格挡（屏障） |

能力牌打出后进入「能力区」，在状态栏旁显示图标，本场战斗内持续，战斗结束清空。

### 3.2 卡牌数据化（重点）

**现状**：21 张卡以 Kotlin 对象写死在 `game/Cards.kt`，加卡要改代码。

**目标**：加 / 改 / 删一张卡只在**一个数据文件**里操作，不碰引擎代码。

**方案**：把所有内容抽成 JSON 资源，启动时解析 + 校验：

```
app/src/main/assets/content/
├── cards.json      ← 卡牌（含能力卡）
├── enemies.json    ← 敌人与出招表
├── acts.json       ← 幕、每幕的敌人池/精英/boss、节点权重
└── relics.json     ← 遗物
```

卡牌一条长这样：

```json
{
  "id": "cleave",
  "name": "横扫",
  "cost": 1,
  "type": "attack",
  "rarity": "common",
  "target": "all",
  "text": "全体 8 伤害",
  "effects": [{ "kind": "damage", "amount": 8, "target": "all" }]
}
```

效果种类沿用现有的 `Effect`（damage / block / draw / energy / apply / heal / selfDamage），能力卡再加 `power`。

**配套保障**

- 解析失败要有明确报错（哪张卡、哪个字段），不能让游戏白屏；
- 加单测校验：id 唯一、引用的卡/敌人/遗物都存在、数值合法；
- 删除一张卡只要删掉那段 JSON，引用它的地方（起始牌组、奖励池）由校验测试报出来。

## 4. 多幕（Acts）

**现状**：只有一幕，11 层地图，顶层 boss「深渊之眼」打完即通关。

**目标**：像杀戮尖塔一样多幕，每幕不同的普通怪 / 精英 / boss；非最终 boss 击败后给奖励再进下一幕。

**方案**

- 幕配置写在 `acts.json`：幕名、楼层数、普通遭遇池、精英、boss、节点类型权重。
- 每幕各自生成一张 11 层地图；通关方式改为「打完最后一幕的 boss」。
- 非最终 boss 击败后进入「幕间结算」：金币 + 卡牌三选一 + **必掉遗物**，然后进入下一幕（血量、牌组、金币、遗物都带过去）。
- 存档要记录当前幕数；楼层显示改为「第 N 幕 · 第 M 层」。

**初版建议 3 幕**，内容规模：

| 幕 | 普通怪 | 精英 | Boss |
| --- | --- | --- | --- |
| 第一幕（现有） | 腐蚀蠕虫 / 铁面守卫 / 盗匪 | 岩石巨像 | 深渊之眼 |
| 第二幕（新增） | 3 种 | 1 种 | 1 种 |
| 第三幕（新增） | 3 种 | 1 种 | 1 种 |

## 5. 遗物系统

**现状**：没有。

**目标**：像杀戮尖塔那样，遗物提供常驻被动；普通小怪小概率掉落，boss 必定掉落。

**方案**

- 遗物 = 描述 + 一组触发器（与能力卡共用同一套事件系统），全局生效。
- 掉落规则（建议）：普通战斗 12%，精英 100%，Boss 100%，宝箱 40%。
- 掉落时弹出遗物获得界面（名字、图标、说明）。
- 状态栏下方显示已持有遗物（横向小图标，点击看说明）。
- 初版 10-12 个遗物，例如：+1 能量但每回合少抽 1 张、战斗开始获得 5 格挡、每回合首次攻击 +3 伤害、金币 +50%、营地回血 +50% 等。

## 6. 共同地基：事件触发系统

能力卡和遗物本质是同一件事——**在某个时机做某件事**。所以先做一套事件：

```
CombatStart / TurnStart / TurnEnd / CardPlayed / AttackDealt / DamageTaken / EnemyKilled / CombatEnd
```

- 能力卡：绑定在战斗内，战斗结束清除；
- 遗物：绑定在整局，跨战斗保留；
- 后续加新卡/新遗物只是往 JSON 里写触发器，不用改引擎。

## 7. 实施顺序

1. **内容数据化**（cards / enemies → JSON + 解析 + 校验测试）——地基，先做。
2. **触发器系统 + 能力卡**（含 6-8 张新卡）。
3. **多幕**（acts.json + 幕间结算 + 存档升级）。
4. **遗物**（relics.json + 掉落 + 展示）。
5. **UI**：出牌框选/弹出特效、状态栏下移、能力区与遗物条。

每完成一步都：本地构建 → 模拟器实测截图 → 提交；最后打 `v0.2.0`。
